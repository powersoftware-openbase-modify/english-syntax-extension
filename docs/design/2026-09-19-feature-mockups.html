13 · 渲染样式优化（深色 / 彩色 / 浅色 三场景对比）

当前卡片是就地替换、裸文本输出——在深色 hero、亮绿色块、白底 Wikipedia 三种背景上对比度/字号/呼吸感全失控。优化方向：容器化 + 明暗自适应 + 字号归一。

现状 深色 hero 页（spring.io/why-spring）

Spring makes programming Java

使 Java 编程更快、更简单、更安全
失控点：译文继承页面白色 → 在深底上还行；但「使」字颜色被页面继承，成分下划线与深底对比随机；字号 30px 原文 vs 13px 译文，翻倍失衡。

现状 亮绿色块页（Spring 绿色背景）

We use a lot of the tools that come with the Spring framework

我们使用很多工具，随 Spring 框架一起提供的
失控点：白字译文 + 灰色下划线在绿色背景上几乎不可读；成分色条被绿底吞没。

现状 白色 Wikipedia 页

The population was 48,604 at the 2021 census.

人口是在 2021 年人口普查时
失控点：白底上勉强可读，但句子间无卡片边界、散装文本无呼吸感；灰色译文与正文混在一起。

优化后 深色 hero 页

优化后 白色 Wikipedia 页

The 主语population 谓语was 48,604 状语at the 2021 census.

人口是在 2021 年人口普查时

修复：白底卡片 + 细灰边框 + 微阴影；句子间有明确视觉边界；译文颜色与正文分离（#374151 vs #202122）。
设计原则： ① 容器化——每个解析结果包裹在独立卡片（.card-dark / .card-frost / .card-lite），不再就地替换原文； ② 明暗自适应——SW 根据页面背景亮度（取段落容器 computed background 亮度均值）选卡片类型：dark（#111827 底）、frost（毛玻璃白底）、lite（白底细边框）； ③ 字号归一——原文 15px、译文 13-14px，无论页面继承多大字号都强制归一； ④ 对比度 ≥4.5:1——WCAG AA 最低标准，成分色条在暗底反色、在浅底饱和； ⑤ 呼吸感——卡片间距 18px、内边距 12-16px、圆角 10-12px，段落节奏清晰； ⑥ 不破坏原文结构——卡片是替换原文段落（BlockReplacement），原文还原时 class 属性按原样保留，不留空 class；⑦ 角色标签居中悬于成分上方——主语/谓语/宾语等小字标签逐个居中悬在对应成分正上方，颜色与该成分下划线一致（对齐真实卡片样式），不做图例色块列表。
